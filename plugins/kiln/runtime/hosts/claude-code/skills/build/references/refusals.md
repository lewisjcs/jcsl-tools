# Refusals and the plan-changed question

`KILN_APPROVED_TASK_CHANGED` on a task plan that `plan-scaffold` wrote means the plan file changed, or the task plan names another ticket reference or plan, since the scaffold: run `plan-scaffold` again and retry `open`. If it repeats on a fresh scaffold, report every line of its `details.lines`, which lists each difference from the approved plan, and stop before `open`. Return a real scope change to kickoff. When the plan file changed since approval, the next command answers with a question instead of an action: show its question and the diff in its detail. Pass the person's yes to continue on the new plan, `change <note>` for a Planner re-plan when the question offers it, or abandon. A question with no yes names what in the file must change first, such as a done task's identity or a file the runtime cannot read: fix the file and run `next`. While a member dispatch is pending, the runtime reads no plan file until that dispatch's receipt: an `open --approved-plan <path>` for another file returns that dispatch with `approvedPlanDeferred: <path>`, and you run it again after the receipt. `KILN_APPROVED_TASK_PLAN_REQUIRED` means that `open` got an approved plan with no task plan and no saved run: generate the task plan as above and pass `--ticket-plan`. `KILN_APPROVED_SOURCE` and `KILN_APPROVED_TICKET` mean that the task plan lacks the approved plan's source or the ticket: generate it again with `plan-scaffold`. `KILN_APPROVED_RUN_NEEDS_RESTART` means that the saved run still waits on discovery or planning: add `--again`. `KILN_OPEN_TITLE` means the `--title` flags do not fit the plan, or a title holds a word a pull request title may not hold: pass one per repository its message names, or one on a plan that names none, and write the title without the named word. It also means that `--title` came without `--ticket-plan`, or on a saved run without `--again`: a new run takes `--title` with `--ticket-plan`, and a saved run takes both only with `--again`, to restart it; to resume a saved run, run the resume form with neither flag. On a run that holds an approved plan, another `--approved-plan` file is a plan change and asks that question; on a run with no approved plan it is still `KILN_APPROVED_PLAN_RUN_MISMATCH`. If `KILN_APPROVED_BASE` says that a checkout names no origin default branch, run `git -C <checkout> remote set-head origin --auto` for the checkout its details name. Retry `open`. If the selected base is absent on that checkout's remote, choose a valid base within the plan and show it. `KILN_APPROVED_REPOSITORY` means that a worktree's checkout is not a repository directly under `KILN_CHECKOUTS`, that two worktrees share one checkout, or that a task's worktree belongs to another repository than the one its approved task names: correct that worktree and generate the task plan again. `KILN_APPROVED_WORKTREE` means that a root is neither the top of a registered worktree nor a missing root under `<checkout>/.worktrees/`: name a valid root. `KILN_APPROVED_WORKTREE_BRANCH` refuses the default branch, and a branch to create that already exists, locally or on the remote: name the worktree that holds that branch, or ask the person for another branch name. If `KILN_APPROVED_WORKTREE_DIRTY` appears, preserve the changes. Find a clean checkout or resume the run that owns them. If `KILN_INSTALL_FAILED` appears or a dependency is missing, run the repository's install command in the worktree. Resume with `next`. If `KILN_ACTION_STALE` appears, read `next` before acting. If measurement fails, inspect the worktree for writes and commits before a retry. Keep approval, state integrity, and measured write refusals in force.
