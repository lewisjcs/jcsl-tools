# Stale replies, abandon, and plan changes

If a `reply` is refused with `KILN_ACTION_STALE` because the command's own plan check just replaced the question with a plan-changed question, read `next` and show the new question. A person can reply `abandon` at any pending action, a member dispatch included: run `reply` with the pending action id and the text `abandon`. At a dispatch, stop the running member before replying `abandon`; commits the member makes after the run ends are not tracked by carry-forward. When the person tells you to change the plan in words, such as `fix the plan: 0.35 to 0.25 in criterion 2 and task 3`, make that change in the plan file yourself, show the diff, and say that you edited on instruction. Then run `next`, or, while a member dispatch is pending, wait for its receipt instead. The runtime asks its plan-changed question over your edit, after the receipt when a member dispatch is pending, and the person's `yes` there rebinds the run. The same holds at the re-plan question (`reform`) that the Inspector raises, or that a Crafter raises on an approved plan: on the person's instruction fix the plan by hand, run `next`, and pass their `yes` to the plan-changed question it returns; or pass `change <note>` at the reform question when they want a Planner re-plan and the question offers it. When a Crafter asks for a file its task does not list, the fix is that file on a file line of its own under that task in the plan, on the person's word: a re-plan cannot add a file on an approved plan. A change that needs a look at the code is the Planner's: pass `change <note>` with the person's words when the question offers it.
