# Codex build host

This is the Codex dispatch portion of the top-level Kiln build skill. Use its approved-plan selection, task scaffold, consent, borrowed review, and terminal pull request rules. Set `PLUGIN_ROOT` to the absolute folder containing the top-level `skills/` and `runtime/` folders. Use `node <PLUGIN_ROOT>/runtime/bin/cli.mjs` as the CLI. Pass `--host codex` on a new `open`. A resumed run reads its saved host. This host accepts approved plans only.

Before `open`, confirm Node 22 or newer, a writable Kiln run store, native `spawn_agent` and `wait_agent` tools, and an active `CODEX_SESSION_ID`. Kiln reads the active turn's model and reasoning effort from that session and saves them with the run. If the ticket is in Jira and `KILN_JIRA_VIEW` is unset, the run reads it through the plugin's hook on the session's Jira tool: when a command refuses with `KILN_JIRA_READ_NEEDED`, call the tool once per key it names and run the command again. Stop before opening a run when a required capability is absent.

Run `plan-approval-check`, `plan-scaffold`, `plan-check`, and `open` as the top-level skill describes. A failed `plan-approval-check` on a plan that a saved run already holds is a changed plan, not a return to kickoff: run `open` with the same `--approved-plan` path and show the question it returns. `open` on a saved approved build reads the plan file as it is now and, when its bytes changed, answers with the plan-changed question. Show the build approval question and every selected worktree, with its branch, its base, and its tasks. Save the person's clear consent with `reply`; do not infer it from a request to discuss the plan. For every result, follow the returned `next` action without reordering it.

Checks come from the approved plan's `Check:` lines, in the result forms this host verifies: `exit N`, an exact numeric count, `a count of at least N`, or a backticked output literal. The preview enforces those forms, so `KILN_CODEX_CHECK_EXPECT_UNSUPPORTED` cannot fire on a previewed plan. If it fires anyway, it is a runtime defect: report it and stop before `open`. Never edit the approved plan to fit a check.

## Native member dispatch

For `hostBinding.kind` = `subagent`:

1. Run `classes --host codex --class <hostBinding.classId> --installed <hostBinding.bodyPath>`. Stop on a mismatch.
2. If `next.before.take` is true, run `writes snapshot --repo <next.write.repoRoot> --out <next.before.path>` before Crafter starts. Before Inspector starts, for each entry of `next.readOnly.repos` whose `before.take` is true, run `writes snapshot --repo <entry.repoRoot> --out <entry.before.path>`. Keep the same baseline on a retry.
3. Spawn exactly one native Codex subagent with `fork_context: false`. Use `worker` for Crafter and `default` for Inspector. Omit a model override so the subagent inherits the active Codex model and reasoning effort saved in `hostBinding`. The prompt must name the exact `next.actionId`, `next.briefPath`, and `hostBinding.bodyPath`. Tell the member to read the role body and brief before work. Give it every exact command in `next.checkCommands`. Each command runs the member's check of the same number: `next` writes those checks, as `{ command, expect, repo }` in check-number order, to `<run dir>/handed/<next.actionId>-checks.json` beside `next.checkCommands`, and the check runner and the measure script read them there. Never write or edit that file. Tell the member to run each check through `tools.exec_command({cmd: "<the exact command>"})` with a literal `cmd` value and to print the returned runner output. The receipt reader looks for that call in the child's rollout. The prompt asks for exactly one JSON outcome array and no prose outside it.
4. Wait for that agent ID to complete. Keep the returned agent ID; never substitute a different child or a parent-thread summary. On an error or interruption, inspect the worktree and keep the Kiln action pending.
5. Run `node <PLUGIN_ROOT>/runtime/hosts/codex/bin/measure.mjs --agent <agent ID> --action <next.actionId> --brief <next.briefPath> --run <run dir> --cli <PLUGIN_ROOT>/runtime/bin/cli.mjs`. For an action with `next.write`, add `--repo <next.write.repoRoot> --before <next.before.path>`. For Inspector, add one `--repo <entry.repoRoot> --before <entry.before.path>` pair per entry of `next.readOnly.repos`, in that order. The script reads the child rollout, checks the final outcome against its Class contract and recorded checks, and writes the output and host-meta files. It refuses if Inspector changed any of those worktrees. If it refuses on a reply or check mismatch, inspect the worktree and send one focused correction to the same subagent. Tell the member to rerun every check if it changed any file, and none if it changed no file; a runner record from before the correction stays valid only while no file in its own worktree changed (ignored files aside). Wait for its corrected result and run measure again with the same agent ID. If measurement still refuses, report the code and leave the Kiln action pending: that is a question for the person, never a reason to do the member's task or write the member's files in this thread. Never write or adjust receipt files by hand.
6. Run `receipt --ticket <ref> --action <next.actionId> --output <run dir>/handed/<next.actionId>-output.txt --host-meta <run dir>/handed/<next.actionId>-meta.json`. Read its ledger outcome and the next action. The runtime, not the host, decides retries and stops.

The check runner executes the saved task check itself and records the command, exit code, and output. Its exit-status line gives silent checks a quote. The member must quote only output that the runner returned. The measure script refuses a complete claim with a failed check, a quote not in the record, or a check record from before a correction when a file in its worktree changed since; it fills command and exit code from the record and notes any difference. It also checks that the child submitted the runner command, belongs to the active parent session, and used the saved model and reasoning effort. The child rollout supplies actual token totals. Codex tool and path enforcement are best effort; the Class binding reports both degradations. A Codex subagent inherits the parent's sandbox and approval mode. Inspector's before-and-after worktree measurement refuses detected writes at receipt time.

## Other actions

For `person`, follow the top-level skill's reply rules, including its release stop. The loop paragraph of the top-level skill holds the rules for `abandon` at a pending dispatch, for `KILN_ACTION_STALE` after a plan check, and for a plan edit on the person's instruction; all three apply here, except that this host cannot pass `change <note>`, because it has no Planner. For `borrowed`, use the pinned `gauntlet:adversarial-review` Class result, not a Party aggregate report:

1. Run `show --ticket <ref>` and confirm the pending borrowed action. Stage one diff per name in `show`'s `phase.repos`, concatenated in that order at `<run dir>/handed/<actionId>.diff`, as the top-level skill describes. For each name, take the record of `show`'s `repos` with that `name` (an older run has one record with no `name`: use it), fetch its `base` from origin, and stage `git -C <root> diff $(git -C <root> merge-base origin/<base> HEAD) HEAD`: the first with `>`, each later one with `>>`. For an older run without `base`, use the default branch named by `git -C <root> symbolic-ref --short refs/remotes/origin/HEAD`.
2. Load the Gauntlet Codex host skill and run that Class over the staged diff as a `code-diff` artifact. Before dispatch, check the installed borrowed Class manifest with `classes --class jcsl:gauntlet:adversarial-review --installed <Gauntlet plugin root>/runtime/classes/adversarial-review.class.json`. Skip Gauntlet triage. Retain the Gauntlet `runDir` returned by `bundle`; its `bundle.json`, `result.json`, and `evidence.json` must be from that one run.
3. Run `borrowed --ticket <ref> --action <actionId> --result <Gauntlet runDir>/result.json --evidence <Gauntlet runDir>/evidence.json --bundle <Gauntlet runDir>/bundle.json --scope branch`. Pass `--root <run store>` when this run uses a nondefault store. The CLI reads the saved Kiln host and staged diff for that pending action, then checks Class identity, Codex host, result/evidence/bundle digest, and the staged diff bytes. A mismatch maps to a `run-incomplete` gap; leave the action pending until the runtime handles that receipt. Write the returned `outcome` array to `<run dir>/handed/<actionId>-output.txt` and `{"modelBinding": {"model": "main-thread"}, "usage": <returned usage>}` to `<run dir>/handed/<actionId>-meta.json`. Omit `toolCalls` when they were not measured, then run `receipt`.

At terminal `complete`, follow the top-level skill's pull request consent and close rules. If a required Gauntlet Codex host or result is unavailable, report the gap and leave the Kiln action pending.

Before each receipt, check that the saved run still names the same pending action. Before reporting completion, confirm `next.terminal` and the saved status. Do not treat a subagent's final message alone as a Kiln result.
