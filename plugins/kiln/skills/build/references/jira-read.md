# Reading a Jira ticket

A Jira key is read in one of two ways, and this release never writes to Jira. If the setting `KILN_JIRA_VIEW` names a command, the runtime runs that command to read the ticket. The setting can also name a script of the person's own that prints one ticket as JSON. With no setting, the runtime reads the ticket through this session's Jira read tool, and it tells you when to call the tool: the refusal `KILN_JIRA_READ_NEEDED` lists ticket keys in `details.keys`. If the session lists that tool by name only, load it first. For each key, call the tool whose name ends in `getJiraIssue` once, with `issueIdOrKey` set to the key and `cloudId` set to the Jira site, and with no other input. A hook sets the other inputs and saves the answer for the runtime. The tool's result is then one line with no ticket text. That is correct: never call the tool again to see the ticket, and never write a ticket file yourself. To find the cloud id, call the tool of the same Jira server that lists the sites you can reach. If it lists more than one site, ask the person which site holds the ticket. If the call fails for one key, go on to the next key. After a `KILN_JIRA_READ_NEEDED` at `open`, run `open` again with the same flags. `open` can ask twice: once for the ticket and once for the tickets that it links to. After a `KILN_JIRA_READ_NEEDED` at a later command, run `next --ticket <ref>`. A command that already saved its state does not refuse for a read, and a command that only shows the run does not refuse either. The `next` of its answer then holds `jiraRead` in place of an action. Read the other fields of that answer as always. Then call the tool once for each key in `next.jiraRead.keys`, and run `next --ticket <ref>`. If the session has no tool whose name ends in `getJiraIssue`, show the refusal's message to the person and stop. For another `KILN_JIRA_` refusal, read the named capture and correct a safe tool or command setup error. Preserve an unreadable capture and report the limit. `KILN_JIRA_NOT_READ` means that no answer was saved: the session has no Jira read tool, the call failed, or the session started before the plugin update. `KILN_JIRA_CAPTURE` means that the saved answer cannot be used, and its message names the kept file. Never run a login for the person. After such a refusal on a later command, resume with `next --ticket <ref>`, not with the command that failed. If `next` names the action whose command failed, run that command again: a `receipt` with its files in `<run dir>/handed/`, a `reply` with the same text from the person.
